# Firmspace AI — план реализации

## Аудит текущего состояния

- GitHub-репозиторий `RustDzhur/ai-agent` содержит статический немецкоязычный лендинг (`frontend/public`) и отдельный Caddy-фрагмент для сайта.
- В репозитории нет API, frontend-приложения workspace, схемы БД, миграций, тестов или Docker-конфигурации приложения.
- На сервере Ubuntu уже работают Docker, Caddy, PostgreSQL 18.6, Redis 8 и MinIO. Все три хранилища проходят health check.
- База `firmspace` создана отдельно и пока не содержит таблиц в схеме `public`. Существующие серверные `.env` содержат секреты; их значения не читались и в Git не попадут.
- Публичный сайт сейчас обслуживается Caddy из `/opt/projects/firmspace/frontend/public`; адреса с `www` и без него покрыты одним Caddy-блоком.
- Локально доступен Node.js 24, но Docker установлен только на сервере.

## Принципы

- Приложение работает на `/app`, API — на `/api/v1`; публичный лендинг остаётся на `/`.
- Интерфейс workspace сначала делается на немецком языке, тексты отделяются от компонентов для последующего добавления English, Russian и Ukrainian.
- Метрики, агенты, задачи и интеграции показываются только после появления реальных данных и работающего backend.
- Каждая операция с данными организации требует серверной проверки членства и роли. Tenant-owned таблицы получают `tenant_id` и защиту PostgreSQL RLS.
- Агентам запрещён прямой доступ к PostgreSQL, Redis, MinIO и файловой системе; будущие действия проходят через ограниченный tool gateway.
- Секреты остаются только в серверном файле окружения с ограниченными правами. Платёжные, финансовые и внешние действия требуют аудита и человеческого подтверждения.

## Результат первого релиза

Первый релиз завершает этапы 1–2 и создаёт честную основу workspace: пользователь может создать аккаунт и организацию, войти, выйти, переключать доступные ему организации и видеть только доступные ему данные. Workspace показывает пустые состояния для ещё не реализованных возможностей. Агентские запуски, интеграции, документы и аналитика не изображаются работающими.

Приложение развёрнуто в отдельном checkout `/opt/projects/ai-agent`. Публичный лендинг продолжает обслуживаться из `/opt/projects/firmspace`; Caddy-конфигурация сохранена отдельно в инфраструктурном репозитории. Проверены production-сборка, готовность API, HTTPS для `/app/` на основном и `www`-именах, сценарии регистрации/входа/выхода и переключения организаций, а также изоляция двух tenants на настоящем PostgreSQL.

## Ограничения текущего выпуска

- Это первый работающий этап платформы, а не завершённый продукт из всех двенадцати этапов выше.
- Каталог и исполнение AI-агентов, интеграции, workflows, загрузка документов, биллинг, API-ключи и аналитика ещё не реализованы. Интерфейс явно помечает эти разделы как находящиеся в разработке.
- Подтверждение адреса электронной почты, сброс пароля, приглашения, MFA и GDPR-процессы ещё не реализованы. Не используйте приложение для хранения чувствительных рабочих данных, пока эти части не будут добавлены.

## Проверки каждого этапа

Для каждого выпуска выполняются форматирование/lint, typecheck, unit и integration проверки по реализованной логике, сборка frontend/backend и проверка Docker image. Security-критерии включают отказ в межтенантном доступе, безопасные cookie/CSRF, ограничение попыток входа, проверку прав на сервере и отсутствие секретов в Git.
