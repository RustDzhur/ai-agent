# Правила работы с репозиторием

- Перед изменениями прочитайте `IMPLEMENTATION_PLAN.md`, `ARCHITECTURE.md` и `SECURITY.md`.
- Не выдавайте концептуальные элементы лендинга за доступные функции workspace.
- Не добавляйте demo tenants, фиктивные метрики, ложные успешные интеграции или запуски агентов.
- Для каждого tenant-owned ресурса создайте `tenant_id`, RLS policies, серверную проверку membership/role и тест межтенантного отказа.
- Все финансовые и внешние бизнес-действия должны иметь approval policy, audit trail и идемпотентность.
- Секреты хранятся только в серверном `.env.app`, который игнорируется Git. Не читайте и не выводите значения секретов в терминал.
- Сохраняйте немецкий текст интерфейса; тексты держите готовыми к дальнейшей локализации.
- Работайте в фазах из implementation plan. Перед следующей фазой запускайте lint, typecheck, unit/integration tests и build.
